EXPLICIT HARD CONSTRAINTS (MUST BE ENFORCED)
🔒 Constraint 1 — Version Hash EXCLUDES Project Metadata
Versioning MUST NOT include:

Project Name
Approving Authority

The same architectural decision reused across initiatives MUST yield the same version. Cosmetic or administrative metadata must not invalidate governance artefacts.


🔒 Constraint 2 — ECP Section Order Is Programmatically Enforced
The ECP consists of exactly nine sections in the following order:

Decision Reference & Authority
Approved Scope & Mandate
Mandatory Architectural Layers
Mandatory Constraint Categories
Integration & Legacy Constraints
Acknowledged Architectural Risks
Trade‑Off Boundary Declaration
Change Control Clause
Disclaimer

This order is immutable.
ECP builder MUST:

accept section definitions
sort by an explicit sectionOrder field
never rely on array order or JSX layout for correctness


🔒 Constraint 3 — Constraint Content Must Stay Category‑Level
ECP content MUST express constraint categories, not implementation controls.
✅ Allowed:

“Security controls are mandatory”
“Operational monitoring is required”
“Auditability is compulsory”

❌ Forbidden:

Technology stacks
Control mechanisms
Tools, products, algorithms, platforms

Rationale:

Step 4 defines execution boundaries, not technical solutions.


🔒 Constraint 4 — Export Preview MUST Be Document‑Like, Not Editor‑Like
The Step 4 preview UI must:

Mirror the exported document layout
Be static and read‑only
Avoid pagination controls, zoom sliders, collapsible sections, or inline editing

Step 4 preview is a visual confirmation, not a working document editor.
