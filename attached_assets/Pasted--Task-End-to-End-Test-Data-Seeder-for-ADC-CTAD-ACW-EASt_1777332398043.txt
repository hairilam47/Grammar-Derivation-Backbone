## Task: End‑to‑End Test Data Seeder for ADC, CTAD, ACW, EAStudio, and Governance

### What & Why
We need a deterministic, repeatable way to populate the entire application with rich, realistic test data. This will let us demo the full system, run manual smoke tests, and catch regressions without navigating through the wizard, CTAD shells, and Authoring Panel dozens of times. The seeder must exercise every major surface: ADC decisions, CTAD architectures (both bound and standalone), ACW/EAStudio authored workspaces, Organisational Units, policy signals, and Track 3 preferences.

The seeder lives as a development‑only route (`/seed-all`) that can be visited in the browser. It deletes all existing localStorage data for the app, then programmatically calls the same store functions the UI uses, so all invariants, validators, and vocabulary guards are enforced exactly as they would be during normal use.

### Design rules
- **Deterministic**: use hard‑coded dates, ids, and names (no `Date.now()` or `Math.random()` inside the seeded data). The goal is that running the seeder twice produces **identical** localStorage state.
- **Safe**: only available when `import.meta.env.DEV` is `true`. In production it is a no‑op.
- **Complete**: seeds at least 3 ADC decisions, 3 CTAD architectures (mix of legacy bound and standalone), 1 full ACW/EAStudio workspace, 2 Organisational Units, and 3 policy signals.
- **Passes all validators**: every value must be within the allowed enums, every text label must pass the vocabulary guard, and every edge must be grammar‑legal. The seeder must **never** trigger a refusal banner.
- **Additive only**: import and call existing store functions (`addOrUpdateEntry`, `createArchitecture`, `setArchitectureParam`, `createNode`, `createEdge`, `updateNodeProperties`, `createOu`, `addSignal`, etc.). Do **not** bypass the validators by writing raw JSON to localStorage.
