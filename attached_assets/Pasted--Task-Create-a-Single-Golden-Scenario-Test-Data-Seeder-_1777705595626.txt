### 3. CTAD – Logical Design Diagrams

All CTAD nodes must be stored in the ACW workspace (`acwStore`) with the appropriate `diagramType` and `diagramSubtype`, linked to Modules and Requirements where specified.

#### 3.1 BPMN – “Border Entry Process”
- Pool: “Border Control”
- Lane: “Officer”, Lane: “Traveller”
- Task: “Scan Passport” (in Officer lane, linked to requirement “Real‑time passport validation” and module `module:border-control`)
- Task: “Verify Biometrics” (in Officer lane, linked to requirement “Fingerprint & facial recognition scanner” and module `module:biometric`)
- Task: “Clear Entry” (in Officer lane)
- Start Event → Scan Passport → Verify Biometrics → Clear Entry → End Event
- Gateway (exclusive) after Verify Biometrics: if failed → “Refer to Secondary” (Task), then End Event.

#### 3.2 ERD – Core Entities
- Entity: “Traveller” (attributes: travellerId PK, firstName, lastName, nationality, passportNumber)
- Entity: “Visa” (attributes: visaId PK, travellerId FK, type, issueDate, expiryDate)
- Entity: “BorderCrossing” (attributes: crossingId PK, travellerId FK, checkpoint, timestamp, decision)
- Relationship: Traveller 1‑N BorderCrossing
- Relationship: Traveller 1‑N Visa

Link the ERD entities to module `module:border-control`.

#### 3.3 DDL – Physical Data Model
- Table: “traveller” (columns: traveller_id PK, first_name, last_name, nationality, passport_number)
- Table: “visa” (columns: visa_id PK, traveller_id FK, type, issue_date, expiry_date)
- Table: “border_crossing” (columns: crossing_id PK, traveller_id FK, checkpoint, timestamp, decision)
- Foreign key: visa.traveller_id → traveller.traveller_id
- Foreign key: border_crossing.traveller_id → traveller.traveller_id

#### 3.4 Sequence Diagram – “Visa Application Flow”
- Lifelines: “Public Portal”, “Visa Service”, “Payment Gateway”, “Biometric Service”
- Messages:
  1. Public Portal → Visa Service: “Submit application (sync)”
  2. Visa Service → Payment Gateway: “Authorise payment (sync)”
  3. Payment Gateway → Visa Service: “Payment confirmed”
  4. Visa Service → Biometric Service: “Request biometric verification (async)”
  5. Biometric Service → Visa Service: “Biometric verified”

Link the sequence diagram to module `module:visa-processing` and requirement “Online payment for visas and permits”.

#### 3.5 Class Diagram – Payment Module
- Class: “Payment” (attributes: paymentId, amount, currency; operations: processPayment(), refund())
- Class: “CreditCard” inherits Payment (attributes: cardNumber, expiry; operation: authorize())
- Class: “OnlineBanking” inherits Payment (attributes: bankCode, accountNumber; operation: authorize())
- Link to module `module:payment`.
