STEP 3 OBJECTIVE (STRICT)
Implement a trade‑off exploration layer that allows users to explore consequence changes without changing architecture structure.
Step 3 exists to answer:

“What happens if we change our posture?”

NOT:

“What is the best design?”
“How should we build this?”
“Which technology should we use?”


FUNDAMENTAL CONSTRAINT (NON‑NEGOTIABLE)

Trade‑offs may affect indicators only.
Trade‑offs must NEVER add, remove, or mutate components.

Any structural change based on trade‑offs is an automatic failure.

INPUTS (CONTROLLED, FIXED SET)

1️⃣ Architecture Posture

"Simple"
"Distributed"

2️⃣ Deployment Posture

"Cloud"
"OnPrem"

3️⃣ Scope Ambition

"Minimal"
"Full"

These map directly to the existing TradeOffSettings type.
❌ No sliders
❌ No numeric tuning
❌ No free‑text
❌ No additional options
